# Commerce ERP · 6.6 库存调整、盘点与隔离处置

本版新增库存调整、良品/隔离盘点、隔离转良品、报损、退供出库记录以及独立冲销。保留原订单、期初、仓储、售后及基础业财流程。本次提供数量管理，不包含期初估值、存货计价或财务凭证。

## 从源码构建

本仓库对应6.6，包含WPF客户端、独立API、数据库工具、测试、文档及带上游许可证的离线依赖。使用Windows x64和.NET 10 SDK（版本见global.json），在仓库根目录执行：

```powershell
./build.ps1
```

构建会运行回归并生成app目录。随后运行Start-Business.cmd建立自己的空工作区。已有测试Fixtures数据库为合成夹具，不是运行库或真实业务数据。verification保留本次验证JSON，界面截图保留在原交付包；测试和构建会更新本机验证结果。

不要提交访问令牌、平台密钥、连接串、账号会话或真实业务数据库。deploy中的example配置只包含示例路径，实际配置请在本机单独创建。离线依赖许可证随lib保留，仓库当前未另行指定项目源码许可证。

## 启动和操作

解压到可写目录，安装Windows x64的.NET 10 Desktop Runtime与ASP.NET Core Runtime，运行 `Start-Business.cmd`。正式工作区无演示业务；`Start-Erp.cmd` 保留演示入口。管理员先维护商品和账号。

进入“库存与可承诺量 → 调整 / 盘点 / 隔离处置”：

1. 新建单据，选择类型，填写唯一单号和SKU编码。
2. 填写数量：调整填正负增减量；盘点填良品在库实盘数及隔离实盘数；隔离处置填正数量，隔离实盘列留0。
3. 点击“核对当前账面”，查看良品/隔离余额、预占和冻结；填写原因及实物核对凭证，保存草稿。草稿不改库存。
4. 退出制单账号，由独立审核账号登录，查询并打开单据，核对“已存良品变动”“已存隔离变动”和依据，审核入账。
5. 若审核提示SKU、库存或隔离版本变化，重新实物核查后修改草稿并刷新版本。未保存的明细/依据修改不能直接审核。
6. 错误草稿可作废。已审核单不能直接改写；选择原单并填写实物更正依据，发起冲销草稿，再由另一账号审核。原单和流水保留，一张原单最多成功冲销一次。

## 权限与数量边界

仓储角色可制单、修改、作废、发起冲销；新增 `InventoryApprover`（库存审核员）可审核但不能制单；观察员可查看。管理员拥有操作权限，但同样不能审核自己创建或修改的单据。账号须有当前仓库及全部店铺范围，因为这些单据改变共享仓库存。

所有行在同一事务内审核，重复操作号返回原结果。任一SKU/库存/隔离版本冲突、数量不足或故障会使整单回滚。数量最多三位小数，绝对余额上限10亿；不能通过盘亏/负调整侵占已预占或冻结的数量，不能改变原订单预占。隔离转良品要求SKU启用。

正式工作区HTTP“快捷补货”已阻止，人工数量变动应使用单据审核；演示快捷补货保留。已有可信内部业务入账不受该界面限制。仅有隔离流水的商品同样不能改单位或组合结构。

## 盘点与隔离说明

盘点是所选普通SKU的实盘记录，不是全仓冻结；未列商品不变。良品实盘数包含仍在仓内的预占/冻结实物，隔离数单独填写，不计ATP。期间有业务变化将拒绝旧版本审核，需要重新核查，不会自动把差异套到新余额。

隔离转良品会增加良品在库并减少隔离；报损和退供仅减少隔离。退供是数量出库记录，必须填写接收方和实物凭证，不包含供应商往来、采购退单、物流接口或自动财务处理。冲销必须确认实物确已纠正；若良品已被后续订单预占/冻结，冲销可能被拒绝，不会强行取消这些业务。

历史售后QuarantineLedger保持不变，新处置记入InventoryMovements，售后核对同时计入两类流水。良品流水通过StockDocumentId关联原单；良品变动同事务生成StockAdjusted事件，尚未配置真实平台处理器。

## 升级

**协议7 / schema10。先完整备份、停止旧客户端和服务并核清未确认请求，同步替换本版客户端/API。** SQLite首次打开自动升级，身份与历史保留。SQL schema9在本机设置ERP_SQL_CONNECTION后执行：

```powershell
./app/tools/CommerceErp.DatabaseTool.exe upgrade-inventory --database 你的业务库名
```

只接受身份有效的schema9，schema10重跑无变更；更早版本依次执行upgrade-accounts、upgrade-tasks、upgrade-master、upgrade-review至9。升级在事务内增加四张库存单据/流水表及主库流水关联，不重置余额。回退须恢复旧备份与旧程序。

`build.ps1` 包含原有回归及22项库存专项；另有HTTP烟测、WPF界面、SQL脚本解析。结果见 [验证汇总](verification/summary.json)、[环境检查](verification/environment-report.json)、[容量原始报告](verification/capacity-report.json)。桌面验证入口为 `--verify-ui <全新目录>` 与 `--verify-master-ui <全新目录>`。

“单据核对”检查已存单据与数量流水；全仓余额/预占仍使用库存一致性检查，退货/隔离使用售后核对。核对不会自动修账。

SQL Server实机、HTTPS/服务账户、恢复演练和生产容量仍未验收。真实电商/财务接口、采购成本与期初估值、部分取消/换货/补发、多仓、库位波次和外部告警仍待开发。下一步建议补期初估值、成本来源与成本更正，见 [开发路线](docs/next-stage.md)。
