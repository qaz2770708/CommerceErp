# 第五步：账单对账、成本快照与财务交接

> 版本说明：本文描述原阶段业务设计。6.2 的认证方式、角色和当前范围以 [账号说明](accounts-security.md) 为准，后续边界以 [开发路线](next-stage.md) 为准。
## 本轮范围

本地 WPF 五个页签：账单导入、流水匹配、订单对账、成本管理、报表与导出。全部命令经本机 ASP.NET Core 服务写 SQLite；操作人是本地标签，没有冒充认证身份。

账单来自人工选择或粘贴的 CSV，未经过平台服务端验签。资金证据维度保持独立：售后人工凭证、导入账单、实际退货和本地出库成本不会相互伪造。账单退款不修改售后 RefundTrackingState，人工 EvidenceRecorded 不生成 BillRows；没有真实退款指令。

## 数据与事务

schema 4 在同一升级事务内增加：

| 表 | 用途 |
|---|---|
| BillBatches | 平台/店铺/批次号唯一，原始文本、映射、请求及内容摘要、导入/重复数量和作废状态 |
| BillRows | 平台/店铺/流水号唯一，原字段及规范化收支、时间、金额、原始业务标识、可审计的订单/售后关联 |
| SkuCosts | 实物 SKU 当前手工单位成本及版本和依据 |
| ShipmentCosts | 原出库行 + 实物 SKU 唯一，数量、冻结单位成本、总成本、版本及来源 |
| OrderFeePlans | 每单应扣平台费、运费、版本和确认依据 |
| FinanceHistory | 导入、匹配、作废、成本、费用及导出事件，不覆盖已有历史 |
| FinanceExports | 不可变 JSON/CSV 内容及摘要；Prepared、Exported 两个本地状态 |
| FinanceExportOrders / FinanceExportRows | 导出和订单/流水的追踪关系及生成时的订单指纹 |

迁移为历史已出库组件建立缺失成本占位，数量取原 ShipmentComponents；不使用当前成本推算历史。缺失记录不阻断仓库既有流程，但会阻断完整利润和财务导出。

所有变更先校验 GUID 操作键、操作人及原因，再在数据库写事务中校验/变更版本、写业务和审计、保存操作结果。SQL 唯一约束和串行写事务同时保护并发。临时忙或未确认请求保留原键重试，不生成新的收货/退款/入账动作。

出库时在仓储事务内调用 CaptureShipmentCosts，库存扣账与成本占位一起提交。财务不会更改 InventoryBalances、Reservations 或 QuarantineBalances。故障注入位置包括 finance-after-row、finance-after-export、finance-before-commit。

## 导入与防重

每批 1–500 行，UTF-8 文本不超过 120 KB；HTTP 仍沿用 256 KB 上限。CSV 支持标准引号转义，要求明确七个列名、四类交易的类型值映射、正数元金额、CNY、带时区时间。退款必须有来源售后编号；非退款行售后列须为空。未知类型、负金额、千分符、精度超限、缺少字段或非法时间整批拒绝。

行的业务摘要由规范化流水号、订单号、类别、分金额、UTC 时刻、售后编号生成；不含操作人、批次或人工关联。相同流水跨文件重复且业务摘要一致时跳过，内容不同则拒绝整批。同批次编号只有文件及映射完全一致才重放。作废记录也保留原业务号，不能通过重导复活。

预览不写业务。桌面保留预览时完整输入签名；内容、映射、平台、批次或文件名变化后，提交要求重新预览。服务端提交再次检查，防止预览到提交之间发生竞争。

BillBatches.State 从 Active 到 Voided，不物理删除；已进入财务交接的流水所属批次不允许作废。当前没有负向冲销账单类型，错误记录通过未导出批次作废和新业务编号更正，导出后的更正另待外部财务流程。

## 匹配及差异

自动匹配使用租户、平台、店铺和原订单号，退款增加来源售后编号，并要求售后已批准或本地结案。先有账单后有订单可重新匹配。已有人工订单关联不会被自动重匹配覆盖。

人工匹配需填写依据，检查同平台同店铺，退款售后必须属于所选订单。保留原 CSV 订单号，只调整关联和版本。已导出流水禁止改关联。有效退款账单关联后，售后不能直接撤回/驳回释放额度，须先处理账单差异。

对账累计每单多笔收入，每个售后多笔退款，不要求交易与业务日期一致。分别检查收入与原单实付、各售后退款与批准金额、平台费与人工应扣费用、运费与人工应扣运费；差异不允许互相抵消。退款没有有效售后、待审核售后、退货未结案、未完全出库、成本缺失都会列为问题。

当前没有“强制对平”按钮。处理通过匹配、补充实际账单、修正费用依据、补录成本或作废未导出错误批次完成，原记录留痕。无法确定的差异继续显示待完善。

## 金额及成本

账单和费用金额以分存整数；库存数量为千分单位；单位成本以百万分之一元存整数，允许六位小数。单位成本范围为 0–1000000 元。出库组件成本 = 数量千分单位 × 单位成本百万分单位 / 10000000，按分四舍五入，半分远离零。

每个出库组件的累计良品冲回 = 原组件总成本 × 累计良品退回数量 / 原组件出库数量，按分舍入。按累计量而非每个收货批次单独舍入，保证全退时恰好冲回原成本。残次不冲回商品成本；零成本必须由操作人显式录入依据。

当前成本是人工标准成本快照，不是 FIFO、移动平均、批次采购成本或财务存货计价。已有成本快照不可修改；仅允许缺失占位补录一次。出库后修改 SKU 当前成本只影响未来出库。

基础结算贡献使用已导入收入减退款、平台费、运费及净商品成本；没有把净到账额再次当作销售额。数据完整且本地金额对平才给出数值，不宣称平台已最终结算。取消未出库订单要求全额退款闭合，实物成本明确为零。

商品分析以原销售 SKU 分组。收入、退款、平台费和运费各自按原行折后商品额分摊；全零时按销售数量分摊。最大余数法分配分位，以原行号排序处理相同余数。组件成本归属原销售行，组合商品汇总组件。商品退款按比例分摊是分析策略，不是实际逐行退款确认。

## 财务导出

服务端可一次选择 1–100 个对平订单，WPF 当前为选中的一个订单生成包。导出编号及操作键防重，同一订单只允许一份交接快照，重复下载返回原内容。包内有 schema、exportId/businessKey、来源、订单、流水和成本快照。

生成包为 Prepared；文件保存成功后登记 Exported，二者均是本地状态。保存文件和登记状态不可能跨文件系统与数据库做同一个事务：若文件已保存但登记失败，使用原未确认请求重试或重新下载同一快照，不重新生成内容。JSON/CSV 分别有摘要；写 CSV 带 BOM，摘要针对去 BOM 的 UTF-8 文本。

生成时保存每单当前指纹，含订单版本、账单关联及版本、退款申请、费用计划和成本/累计良品冲回。之后查询导出会计算是否过期，不自动重写旧包。当前不实现外部已接收、已记账或已冲销状态，避免把 HTTP 或文件写入成功当作记账成功。

## HTTP 入口

全部入口使用既有 X-Erp-Session 本机凭证。

| 方法与路径 | 用途 |
|---|---|
| POST /api/finance/preview | BillInput 预览，无副作用 |
| GET / POST /api/finance/batches | 批次列表 / 导入 |
| GET /api/finance/batches/{id}/original | 读取保留的原文 |
| POST /api/finance/batches/{id}/void | 带版本作废 |
| GET /api/finance/rows | 分页、搜索及 unmatched 筛选 |
| GET /api/finance/rows/{id} | 原始字段和关联历史 |
| POST /api/finance/rows/{id}/match | 人工关联 |
| POST /api/finance/rematch | 重新自动匹配未完成关联 |
| GET /api/finance/orders | 分页、搜索及 differences 筛选 |
| GET /api/finance/orders/{id} | 差异、费用、成本和账单明细 |
| POST /api/finance/orders/{id}/fees | 应扣费用及依据 |
| GET /api/finance/sku-costs | 单位成本列表 |
| POST /api/finance/sku-costs/{id} | 单位成本版本更新 |
| GET /api/finance/costs?order= | 所有/指定订单出库快照 |
| POST /api/finance/costs/{line}/{sku} | 缺失历史成本补录 |
| GET /api/finance/report | 累计店铺和销售 SKU 汇总 |
| GET / POST /api/finance/exports | 导出列表 / 生成不可变包 |
| GET /api/finance/exports/{id} | 下载内容、摘要、历史及过期标志 |
| POST /api/finance/exports/{id}/saved | 登记本地文件保存 |
| GET /api/finance/audit | 结构、原文、成本和导出摘要核对 |

命令类型在 FinanceModels.cs。错误输入为 400，版本/状态冲突为 409，数据库忙为 503；预览返回 Valid=false 和可读错误，不能仅按 HTTP 200 判断格式通过。财务结构审计通过不等于业务账单全部对平。

## 仍需后续开发

具体平台的官方账单适配、到账/提现与结算的独立核对、负向费用和费用返还、平台订单/售后真接入、期间关账、成本更正、采购成本计价、财务科目/税额/凭证映射、回执/冲销以及生产级权限和共享服务尚未实施。已有接口和报表基于本地模拟租户，不能直接用于真实店铺生产记账。
